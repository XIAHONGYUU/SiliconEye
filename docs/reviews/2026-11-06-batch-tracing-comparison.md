# 六条长线批量追踪对照（2026-11-06）

本轮两个执行 Agent 加独立裁判 Agent，主 Agent 重放和复核。结论：脊线图搜索具有批量生成候选的实际计算速度优势，但首次交付仍比纯视觉手工方式慢，尚未证明端到端人工工作提速。未修改正式几何、连接、原图或生产源码。

## 范围与结果

同一 M3 原图，范围 [200,2200,3700,2500]，六个共享起点；每条追踪 x=250 至3650。执行方不得读历史轨迹和另一分支。裁判提前冻结210个历史AI参考点，排除6个共享起点，以204个保留点作参考一致性评价；不是人工真值。

算法首次多30.011秒（约23.0%）。五次重复计算中位0.748秒，包含读图、滤波、六线追踪，排除进程启动、文件写出和人工检查；主Agent独立重放0.789秒且结果完全一致。不能用130.721/0.748宣称整流程提速倍率。手工重复渲染也不是重新识别时间。

算法为Gaussian亮脊响应、局部峰值候选节点、动态规划连续路径；未使用FLD、SAM或新安装依赖。首次不约束局部峰值的版本严重串线，六条线终点只剩两组，3333/3401列存在相邻轨合并；失败原稿保留。一次修改算法约束后通过当前区域检查，没有手工改路径坐标。

算法平均参考偏差较小，但2px内点数和最大偏差略差，不能宣称全面更准。旧参考本身采用过亮度峰值辅助，可能与当前算法具有相关偏差；裁判另抽查四处原图共24个位置，未见最终串线。主Agent复查中段叠加，结果与裁判一致。

## 独立验证和限制

- 主Agent重放结果精确一致；空白图、40px缺失段均明确报无支持路径，连续斜线可返回。断裂目前使整个调用失败，尚无部分成功交付机制。
- 算法方合成平行斜线测试最大偏差0.48px。三份脚本Ruff通过。手工render原稿存在格式/zip lint问题，仅整理格式并添加strict，原稿保留，所有重渲染图哈希不变；原计时未改。
- 仅连续、近水平、亮色分离长线；未验证转折、分叉、交叉、暗线、跨层、线宽、孔和电气网络。
- 基线是纯视觉标点，未复现历史上包含峰值辅助的全部工作方式。单次不同Agent墙钟含模型/工具延迟，未测实际人的审核和修正耗时。
- 固定只读对照页构建成功。浏览器安全策略拒绝file://导航，未做浏览器交互验收，未尝试绕过；叠加PNG已直接检查。
